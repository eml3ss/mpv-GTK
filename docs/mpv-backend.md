# Штатный libmpv в одном GTK-окне

Приложение использует официальный C API неизменённого `libmpv.so.2`.
Копии установленной библиотеки и CLI лежат рядом с проигрывателем; версия,
источник и SHA256 записаны в `stock-mpv.json`. RUNPATH `$ORIGIN` выбирает эту
обычную библиотеку. Системный mpv не заменяется.

Для встраивания выбирается `vo=libmpv`. Штатный OpenGL Render
API рисует видео в framebuffer `GtkGLArea`, а GTK размещает интерфейс поверх
него. Видео и элементы управления принадлежат одному нативному Wayland-окну.
Собственных рендереров, модификаций mpv, чтения кадров через CPU и отдельного
окна видео нет.

Выбор VO фиксируется после чтения конфигурации, включая отложенные include
и профили. Это необходимое условие стандартного Render API: `gpu/gpu-next`
относятся к самостоятельным видеовыводам mpv, а не к этому встраиванию.
Настройки в файле сохраняются; неподдерживаемый VO не создаёт второе окно.

Начальная загрузка файла запускается до инициализации GTK: mpv успевает читать
файл и находить дорожки параллельно подготовке интерфейса. Барьер
`on_preloaded` останавливает его перед созданием видеовывода; GTK создаёт
общий GL-контекст и Render API, после чего снимает барьер. Окно показывается
после загрузки медиа, без предварительного показа пустого проигрывателя.
Для изолированного движка явно заданы каталоги состояния `watch_later` и
кэша GPU-шейдеров: `config=no` отключает их автоматический поиск в mpv.
Пользовательские пути из `mpv.conf` имеют приоритет.

Пример обычного конфига рядом с программой:

```ini
vo=libmpv
gpu-api=opengl
opengl-es=auto
hwdec=auto-safe
```

Доступны Auto, OpenGL и OpenGL ES; Vulkan виден серым и не выбирается.
Стандартный Render API mpv 0.41 не выдаётся за gpu-next/Vulkan.
Поддерживаемая пара GPU API/OpenGL ES сохраняется в `mpv.conf` атомарно и
применяется после перезапуска. Остальные базовые настройки применяются сразу.

Старые renderer-ключи версии 0.10 мигрируют из `interface.conf`; явные значения
mpv имеют приоритет. Include и профили обрабатывает сам mpv. Язык, задержка
курсора, пользовательские клавиши и прочие параметры сохраняются.

Нижняя панель и информация по ЛКМ — GTK-оверлеи внутри того же окна, ПКМ
открывает отдельное окно сведений. Полный экран и курсор обслуживает GTK.
Frame clock интерфейса работает независимо от видео; ожидание целевого времени
кадра выключено через `MPV_RENDER_PARAM_BLOCK_FOR_TARGET_TIME=0`, а
`video-timing-offset=0` не добавляет опережение перед предъявлением кадра GTK.

Автоматические проверки подтверждают настоящую обработку опций, include,
профилей, событий, клавиш, настроек и реальные пиксели обычного GL/GLES Render
API. В среде без доступного Wayland-дисплея GUI проверка пропускается. Отдельный
headless-тест требует ровно один xdg_toplevel, настоящие видеопиксели и PNG;
если среда не поддерживает его compositor, он возвращает 77, а не ложный PASS.
