# mpv GTK 0.15.2

Нативный интерфейс на GTK4 и libmpv. Элементы управления обновляются по часам GTK, независимо от частоты кадров видео: низкий FPS и пауза не должны замедлять интерфейс.

## Сборка и запуск

Для Arch Linux нужны `gtk4` версии 4.22 или новее, установленный `mpv`, `libepoxy`, `gcc`, `make`, `python` и `pkgconf`. Для генерации тестовых клипов нужен `ffmpeg`, для проверки ярлыка — `desktop-file-utils`.

`make` копирует неизменённые системные `mpv` и `libmpv.so.2` рядом с приложением и собирает GTK-интерфейс. Исходники mpv, Meson и собственные патчи рендерера не нужны. Версия, исходные пути, контрольные суммы и лицензии сохраняются вместе с движком. [Происхождение штатного mpv](tools/RENDERER-SOURCES.md).

```sh
make
./build/mpv-gtk
./build/mpv-gtk /путь/к/видео.mkv
./build/mpv-gtk 'https://example.org/video.mp4'
```

Установка для текущего пользователя, без `sudo`:

```sh
make install
make uninstall
```

По умолчанию настоящий исполняемый файл, `mpv.conf`, `input.conf`, `libmpv.so.2` и `mpv-engine` устанавливаются в `~/.local/share/mpv-gtk/`, ссылка для запуска — в `~/.local/bin/mpv-gtk`, ярлык — в `~/.local/share/applications`. Можно задать другой `PREFIX`; ярлык содержит абсолютный путь к ссылке запуска. Если установлен `desktop-file-validate`, `make install` проверяет ярлык перед установкой. Установку и удаление следует выполнять с одинаковым `PREFIX`.

Обновление через `make install` сохраняет существующие настройки. `make uninstall` удаляет программу, ссылку и ярлык, оставляя `mpv.conf`, `input.conf` и `interface.conf`. `make clean` также сохраняет эти файлы в `build/`.

Разделы настроек создаются при первом выборе; список привязок и каталог команд mpv запрашиваются только при открытии «Клавиши». Содержимое очереди создаётся при её открытии. Параметры настроек наблюдаются, пока окно настроек открыто, а статистика воспроизведения запрашивается раз в секунду только для открытых сведений.

Штатный mpv читает `mpv.conf`, include-файлы и профили до создания GTK-окна. Для встраивания в одно окно фиксируется `vo=libmpv`, а OpenGL/OpenGL ES выбирается до создания общего контекста GTK. Открытие файла, демультиплексирование и поиск дорожек начинаются до инициализации GTK и выполняются параллельно с подготовкой интерфейса. Штатный барьер `on_preloaded` удерживает запуск видеовывода до готовности GL-контекста. При запуске с файлом окно появляется после загрузки медиа; ошибка загрузки показывает сообщение. Без файла окно появляется после подготовки движка.

Скомпилированные GPU-шейдеры сохраняются в `$XDG_CACHE_HOME/mpv-gtk/shaders` (обычно `~/.cache/mpv-gtk/shaders`), чтобы mpv мог использовать их при следующих запусках. Каталог создаётся по необходимости самим mpv. Параметры `gpu-shader-cache-dir` и `gpu-shader-cache=no` в `mpv.conf` сохраняют приоритет.

Используемые значки встроены в исполняемый файл: небольшой набор SVG из Papirus и встроенные ресурсы GTK для стандартных элементов управления. Поиск значков по каталогам пользовательских и системных тем отключён только внутри плеера; большой каталог Papirus при запуске больше не обрабатывается. Символические значки наследуют цвета GTK и акцент темы, а форма значков фиксирована. Логотип окна, экрана без файла и ярлыка одинаковый. Лицензия и происхождение значков находятся в `data/icons/`, после установки — в `icon-licenses/` рядом с плеером.

На NVIDIA автоматический interop подготавливает CUDA для NVDEC и совместимых режимов, пропуская ненужные драйверы. NVDEC, программное декодирование и режимы копирования переключаются во время работы; для другого аппаратного семейства настройка сохраняется до перезапуска и отмечается в описании. Явный `gpu-hwdec-interop` из `mpv.conf` имеет приоритет.

Для замера этапов запуска можно выполнить `MPV_GTK_STARTUP_TRACE=1 mpv-gtk /путь/к/видео.mkv`. Диагностика пишет в терминал время подготовки движка, постановки файла на загрузку, инициализации GTK/GL, настройки встроенных значков, получения событий медиа, запроса показа окна и отрисовки первого видеокадра; обычный запуск ничего не выводит. Эти отметки начинаются при входе в `main` и не включают работу системного загрузчика до него или время фактического показа кадра композитором.

Английские переводы хранятся в `locales/en.ini` рядом с настоящим исполняемым файлом. `make` и `make install` размещают этот ресурс автоматически. Русский интерфейс не загружает словарь; английский загружает его при первом обращении, а смена языка освобождает каталог. При переносе программы нужно копировать и папку `locales`; без неё используются русские исходные строки.

## Управление

Открытие файлов и URL, перетаскивание файлов, боковой плейлист, выбор звуковой дорожки и субтитров, изменение скорости и полноэкранный режим.

Кнопки перехода к предыдущему и следующему файлу появляются только при двух и более файлах в очереди.

Меню с тремя точками в заголовке содержит «Новое окно» и «О программе». Новое окно открывает отдельный пустой плеер; окно сведений показывает значок, версию и компоненты приложения.

В оконном режиме нижняя панель занимает всю ширину и расположена под видео. В полноэкранном режиме она скрывается через 250 мс после завершения взаимодействия. Движение указателя возле нижнего края возвращает её; во время перемотки или работы с открытым меню панель остаётся видимой. Указатель скрывается отдельно: задержка настраивается в «Интерфейс → Скрывать курсор через» от 0,1 до 10 секунд с шагом 0,1; значение показывается как `1.0 s`, исходное — 3 секунды. Отдельный GLib-таймер отсчитывает срок от последнего движения или щелчка мыши независимо от кадров GTK. Меню и перетаскивание удерживают курсор видимым, но их завершение не добавляет новый интервал. Перетаскивание полосы воспроизведения сразу перематывает видео, а отпускание уточняет конечную позицию.

Обычный щелчок по значку громкости включает и выключает звук; средняя кнопка открывает меню аудиодорожек, правая переключает на следующую. Для субтитров и скорости предусмотрены отдельные кнопки. Правый щелчок по скорости добавляет 0,25×, средняя кнопка возвращает 1×. Правый щелчок по субтитрам переключает дорожку, средняя кнопка возвращает выбор, сделанный mpv при загрузке текущего файла, включая отключённые субтитры. При переключении аудиодорожек или субтитров правой кнопкой либо хоткеями на 0,8 секунды появляется компактное уведомление с фактически выбранной дорожкой внизу видео, над панелью управления. Пользовательские бинды mpv тоже поддерживаются; первоначальный выбор при загрузке, выбор из меню и сброс средней кнопкой уведомлений не вызывают. Правый щелчок по видео переключает паузу; эту привязку можно изменить в «Клавиши» или `input.conf`. Настройки разделены на страницы «Видео», «Звук», «Субтитры», «Воспроизведение», «Клавиши» и «Интерфейс»; кнопки открытия `mpv.conf` и `input.conf` всегда доступны внизу. Цвета и акценты берутся из темы GTK. Значки воспроизведения, паузы и перехода между файлами рисуются отдельно и наследуют цвет текста темы.

Видео рисует неизменённый libmpv через штатный OpenGL Render API внутри `GtkGLArea`. Видеокадр, нижняя панель, меню и информация находятся в одном нативном Wayland-окне. Собственного рендерера, патчей mpv и чтения видеокадров в память CPU нет.

Параметр `vo=libmpv` задаётся интеграцией после чтения include и профилей, чтобы `vo=gpu` или `vo=gpu-next` из конфигурации не создавали отдельное окно. Качество, аппаратный декодер, дорожки и другие поддерживаемые параметры mpv продолжают читаться из `mpv.conf`.

Доступны Auto, OpenGL и OpenGL ES. Их выбор сохраняется настоящей парой `gpu-api` / `opengl-es` и применяется после перезапуска. Vulkan виден серым и недоступен: в этом стандартном Render API его нет. `gpu-next` и Vulkan не выдаются за поддерживаемые встроенным выводом. [Устройство взаимодействия](docs/mpv-backend.md).

Статистика показывает фактический GL API, декодер и пропуски кадров. ЛКМ показывает тематический GTK-оверлей поверх видео, ПКМ открывает отдельное окно информации. Полный экран и курсор принадлежат общему GTK-окну.

В оконном режиме панель расположена под областью воспроизведения и не перекрывает обложку аудиофайла. В полном экране аудио и видео используют одинаковое поведение: панель появляется поверх изображения и автоматически скрывается, дополнительное место под неё не резервируется.

Клавиша `I` или обычный щелчок по кнопке информации показывают и скрывают сведения поверх видео. Щелчок правой кнопкой по тому же значку открывает отдельное окно. Панель показывает параметры видео и звука, фактический декодер, пропущенные кадры, рассинхронизацию звука и видео и, при наличии, состояние кэша. Данные обновляются раз в секунду; `Escape` сначала закрывает сведения поверх видео, затем позволяет выйти из полноэкранного режима. Исходные сочетания ниже можно изменить на странице «Клавиши».

| Клавиша | Действие |
| --- | --- |
| `Space` | Пауза / воспроизведение |
| `F` | Полноэкранный режим |
| `←` / `→` | Перемотка |
| `↑` / `↓` | Громкость |
| `Ctrl+O` | Открыть файл |
| `Ctrl+L` | Открыть URL |
| `Ctrl+,` | Настройки |
| `I` | Показать / скрыть информацию поверх видео |
| `Escape` | Скрыть информацию; выйти из полноэкранного режима |
| `M` | Выключить / включить звук |
| `,` / `.` | Предыдущий / следующий кадр |
| `PageUp` / `PageDown` | Предыдущий / следующий файл в плейлисте |
| `Ctrl+PageUp` / `Ctrl+PageDown` | Предыдущая / следующая глава |

В файлах с главами рядом с кнопкой очереди появляется кнопка «Главы». Левый щелчок открывает компактный список названий и времени начала с выделением текущей главы; щелчок по строке перематывает к её началу. Правый щелчок по кнопке сразу переходит к следующей главе. Начала глав также отмечены на полосе воспроизведения. Кнопки в меню и `Ctrl+PageUp` / `Ctrl+PageDown` переключают главы. Переход назад учитывает `chapter-seek-threshold` mpv: после нескольких секунд внутри главы он возвращает к её началу. Переход вперёд останавливается на последней главе файла. Содержимое меню создаётся только при его открытии.

## Клавиши

В «Настройки → Клавиши» показаны текущие привязки интерфейса и mpv, их источник и состояние. Неактивные стандартные привязки mpv остаются выключенными, пока их явно не назначить. Поиск находит клавишу, команду или описание. Можно записать сочетание нажатием, добавить привязку, изменить команду и аргументы либо отключить действие.

Сочетания выделены компактными плашками в общей колонке без переноса строк. Например, `Alt+KP_SUBTRACT` показано как `Alt+Num −`; полная запись доступна в подсказке. На время записи окно запрашивает передачу системных сочетаний у Wayland, чтобы они попадали в редактор. Запрос снимается после записи, отмены, потери фокуса или закрытия окна. Обычный `Esc` отменяет запись; сочетания с `Esc` можно назначать.

Каталог берётся из текущей libmpv: в проверенной версии доступны 85 команд с описаниями на русском и английском, фактическими именами и типами аргументов, необязательными параметрами и примерами. Отдельный список предлагает 42 готовых действия: паузу, перемотку, громкость, скорость, дорожки, главы, снимки, задержки и действия интерфейса GTK.

Описание привязки учитывает операцию, распространённые свойства и аргументы: например, изменение контраста, выбор дорожки, сдвиг субтитров или открытие статистики. Разная запись числа не требует отдельного готового действия.

«Сохранить» записывает изменение в `input.conf` и сразу применяет его через перезагрузку привязок. «Отменить изменение» удаляет только назначение, сделанное в этом окне, возвращая исходную привязку из файла или проигрывателя; строки, добавленные вручную, сохраняются. Встроенные сочетания интерфейса тоже проходят через mpv, поэтому пользовательские имена клавиш и последовательности имеют единый обработчик. В текстовых полях сохраняется обычное редактирование GTK. Пользовательские привязки кнопок мыши обрабатываются над видео.

## Почему интерфейс не зависит от FPS

`GtkGLArea` работает с `auto_render=FALSE`: последний видеокадр сохраняется, а GTK может отдельно обновлять кнопки, меню и анимации. Плавное движение ползунка использует frame clock GTK и интерполяцию позиции между событиями mpv.

В режиме `libmpv` каждый вызов Render API получает `MPV_RENDER_PARAM_BLOCK_FOR_TARGET_TIME=0`. Рендер не ждёт времени показа следующего кадра в главном потоке GTK. Уведомления libmpv будят главный цикл через `eventfd`, команды и изменения свойств используют асинхронный API. `MPV_RENDER_PARAM_ADVANCED_CONTROL` выключен.

Это устраняет ожидание видеотайминга в GTK. OpenGL-рендер выполняется в главном потоке: тяжёлые шейдеры, масштабирование и перегрузка GPU всё ещё способны задержать интерфейс. 

Для встроенного `libmpv` в Wayland доступны desktop OpenGL и OpenGL ES. В режиме Auto выбор делает GTK; явный выбор применяется до инициализации GTK одновременно к общему контексту дисплея и видеовиджету. Функции GL загружаются через EGL. Для интерфейса по умолчанию используется `GSK_RENDERER=opengl`, чтобы не переносить GL-текстуры в Vulkan; явно заданная переменная `GSK_RENDERER` имеет приоритет. Ошибки создания видеоконтекста показываются только в верхней полосе. Шрифт времени — Adwaita Sans с цифрами одинаковой ширины.

## Конфигурация

`mpv.conf` и `input.conf` находятся рядом с настоящим исполняемым файлом. При запуске из сборки это `build/`, после установки — `~/.local/share/mpv-gtk/`. Путь определяется через `/proc/self/exe`, поэтому запуск через ссылку из `~/.local/bin` использует те же файлы.

Команда `quit-watch-later` сохраняет позицию и поддерживаемые параметры в `watch_later/` рядом с конфигом; при повторном открытии файла mpv продолжает с сохранённого места. Путь можно изменить параметром `watch-later-dir` в `mpv.conf`; `resume-playback=no` отключает восстановление. Глобальные конфиги mpv для этого не загружаются.

При закрытии окно сразу скрывается, а запрос скрытия отправляется Wayland-композитору до освобождения GPU. Проигрыватель завершает штатный `quit` при ещё действующем GL-контексте и подтверждает оставшиеся кадры без рисования, чтобы не ждать таймаута видеовывода. `quit-watch-later` и `save-position-on-quit` сохраняют своё обычное поведение.

Если файл отсутствует, создаётся начальный конфиг. При первой установке или запуске прежние `~/.config/mpv-gtk/mpv.conf` и `input.conf`, если они есть, переносятся копированием в новое расположение. Существующие файлы рядом с программой имеют приоритет и не перезаписываются при обновлении. Обычные конфиги `~/.config/mpv/` не меняются и не загружаются; глобальные скрипты mpv тоже не загружаются.

`input.conf` явно загружается libmpv при запуске. В начальном файле есть только комментарии с примерами; удалите `#` перед нужной привязкой и перезапустите проигрыватель. Например, `p cycle pause` назначает паузу на `p`, а `Ctrl+s screenshot` — снимок кадра на `Ctrl+S`. Пользовательские привязки из основной секции файла имеют приоритет над исходными сочетаниями интерфейса, размещёнными в отдельной секции mpv. Изменения обоих конфигов в текстовом редакторе требуют перезапуска; изменения `input.conf` также подхватываются при следующем сохранении на странице «Клавиши».

Окно настроек сохраняет аппаратное декодирование, пропорции изображения, деинтерлейсинг, deband, задержку звука и субтитров, масштаб субтитров и повтор файла. Изменения применяются к текущему проигрывателю и записываются в `mpv.conf`. Отдельно отображается фактически используемый аппаратный декодер: запрошенный режим может перейти на программное декодирование, если устройство или формат не поддерживается.

В разделе «Звук» можно выбрать способ аудиовывода (`ao`) и устройство (`audio-device`). Списки поддерживаемых способов и доступных устройств запрашиваются у mpv при открытии раздела; изменения применяются сразу и сохраняются в `mpv.conf`. При выборе другого способа вывода несовместимое с ним устройство сбрасывается на автоматический выбор. Сохранённые вручную значения, которых нет в текущем списке, остаются видимыми.

В разделе «Воспроизведение» добавлена группа Autocreate Playlist: отключённое автосоздание, соседние файлы выбранных категорий (`filter`) или той же категории (`same`). Здесь же задаются обход вложенных папок и категории `video,audio,image,archive,playlist`; пустой список категорий включает все файлы. Списки расширений видео, звука, изображений, архивов и плейлистов доступны в раскрываемом блоке. Эти параметры сохраняются в `mpv.conf` и действуют при следующем открытии файла или папки; текущая очередь не пересобирается. При явном выборе нескольких файлов создаётся очередь из выбранных файлов.

На странице «Интерфейс» настройки Allow replace и Add video to queue определяют открытие и перетаскивание файлов. Добавление в очередь имеет приоритет и сохраняет текущий файл, позицию и паузу; иначе разрешённая замена открывает выбранные файлы вместо текущей очереди. Если оба режима выключены, открытый файл не меняется. Пустой проигрыватель всегда начинает воспроизведение. Правила сохраняются в `interface.conf`; по умолчанию замена разрешена, добавление выключено.

На странице «Интерфейс» можно переключить русский и английский язык без перезапуска. Выбор сохраняется отдельно в `interface.conf` рядом с `mpv.conf`; настройки интерфейса не передаются libmpv. При отсутствии выбора используется русский язык. Системные кнопки нативного диалога файлов следуют языку рабочего стола.

Числовые поля подтверждают введённый текст по Enter, при переходе к другому полю, щелчке по пустому месту и закрытии окна настроек. Кнопки «+» и «−» сразу применяют и сохраняют новое значение. Задержка курсора записывается с одним знаком после точки, как в самом поле.

При сохранении сохраняются неизвестные приложению параметры, комментарии и пользовательские профили. Запись выполняется атомарной заменой с сохранением прав файла. Приложение задаёт параметры своей работы: idle, запуск вывода при загрузке файла и обработку клавиш интерфейса. Для одного окна приложение резервирует `vo=libmpv` и `video-timing-offset=0`; прочие поддерживаемые настройки берутся из обычного конфига mpv. Старые VO/API-ключи `interface.conf` переносятся только в отсутствующие параметры `mpv.conf`; явные настройки, include и профили имеют приоритет.

## Проверка

```sh
make test
./build/mpv-gtk --self-test=8 /путь/к/видео.mkv
```

`make test` запускает C-тесты модели времени, скрытия панели и указателя, сохранения конфигов, пользовательских привязок клавиш, каталога команд, русского и английского языка, числовой локали, настроек и перемотки во время перетаскивания, EGL-рендер desktop GL и GLES без дисплея (`tests/render.c`), проверку движка (`tests/engine.py`) и графический smoke-тест (`tests/smoke.py`). Тест конфига проверяет сохранение комментариев, профилей, прав и пользовательского `input.conf`, начальную миграцию и путь при запуске через ссылку. Тест каталога сверяет описания и аргументы со всеми командами реальной libmpv без их выполнения. Тест языка проверяет отдельный файл настроек интерфейса, сохранение выбора и безопасное поведение при неизвестном языке. Дополнительно проверяются реальные параметры stock mpv, includes/профили, принудительный встроенный VO после include/профилей, отложенный Render API до готовности GtkGLArea, применение GL API после перезапуска и миграция старой конфигурации. Для изоляции тестов доступен `MPV_GTK_CONFIG_FILE`.

EGL-тест использует Mesa llvmpipe и проверяет готовые пиксели, а не доступ к видеокарте или Wayland. Код выхода `77` у smoke-теста означает пропуск при отсутствии доступного дисплея. Режим `--self-test=SECONDS` предназначен для автоматического завершения и вывода метрик обновления интерфейса и видео; по ним можно сравнивать видео с низким FPS и паузу. Графическая проверка требует работающего сеанса и OpenGL; наличие успешной сборки само по себе не подтверждает плавность на конкретной системе.
